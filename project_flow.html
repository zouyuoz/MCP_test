MCP Server & DeepAgents 運作流程

從自然語言提問、MCP 協議通訊，到資料庫/JSON 動態運算的完整鏈路

1
MCP Server 啟動與工具註冊 (server.py)
以標準協議 (stdio) 啟動微服務，向外宣告具備的 API 工具能力。
• 註冊工具 1：get_oee_detail (查詢區間工時、平均稼動效率)
• 註冊工具 2：get_low_efficiency_lines (診斷效率 < 80% 的異常產線)
• 傳輸模式：stdio (標準輸入輸出，跨進程安全通訊)
2
DeepAgents 連線與工具探索 (run_deepagent.py)
Agent 初始化時向 MCP Server 發送交握與工具清單請求。
• 透過 MultiServerMCPClient 連接子進程 server.py
• 自動取得 Tools 的 JSON Schema (含參數型態、說明文件 docstring)
• 將 MCP Tools 封裝並綁定給 LLM (Google Gemini / OpenAI / Claude)
3
使用者輸入與 LLM 意圖推理 (ReAct 決策)
接收使用者提問，LLM 自主判斷需調用哪些 MCP 工具。
• 使用者 Prompt：「請幫我分析 8/15 ~ 8/17 的 OEE 狀況，並列出效率低於 80% 的產線。」
• LLM 決策：產生 Tool Call 參數（例如 {"start_date": "2026-08-15", "end_date": "2026-08-17"}）
4
資料讀取、去重與指標運算 (oeedetail.json)
server.py 收到呼叫請求，執行業務邏輯並返回結構化 JSON。
• 讀取 oeedetail.json 原始 Kafka 事件流
• 執行 Upsert / 去重 (依 SYNCID 與 SYNCACTION 處理新增/更新/刪除)
• 即時運算 Summary 指標：$\text{總出勤} = 570\text{h}, \text{總損失} = 96.6\text{h}, \text{平均效率} = 83.05\%$
5
LLM 彙整與最終回覆 (Final Response)
LLM 接收 MCP 回傳的真實數據，組織成結構清晰的專業分析回覆。
• 📊 總體數據總結：出勤工時、標準工時、損失率與全廠平均效率
• ⚠️ 精準異常定位：指出 LINE_TEST_01 效率僅 68.0% (損失 25.6 小時)

📁 server.py

MCP Server 核心。定義工具、參數防呆、載入資料並提供標準 stdio API 介面。

📁 oeedetail.json

模擬 Data Portal 訂閱的 Kafka OEE 事件資料，支援時間維度與字串數值防護。

📁 run_deepagent.py

DeepAgents 主調度程式。連接 MCP Server、綁定 LLM (Gemini/OpenAI) 並執行問答。
